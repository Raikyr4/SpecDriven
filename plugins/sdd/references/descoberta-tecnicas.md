# Técnicas da descoberta

Lido pelo `/descobrir` quando a conversa precisa de uma técnica. Use **uma ou duas** por sessão,
as que destravam a lacuna que você vê; não aplique todas.

| Lacuna | Técnica | Como aplicar em uma rodada |
| --- | --- | --- |
| A ideia vem como solução ("queremos um app") | **5 porquês** | Pergunte por que a solução é necessária até chegar a um problema observável (3 a 5 níveis). O problema vai para o brief; a solução vira uma opção. |
| Não está claro para quem é | **Jobs to be done** | "Quando <situação>, quero <motivação>, para <resultado>." Uma frase por perfil afetado. |
| Sucesso vago ("melhorar a experiência") | **Métrica-alvo** | Peça o número de hoje, o número desejado e o prazo. Sem número, a métrica vai para Perguntas abertas. |
| Otimismo demais | **Pre-mortem** | "Daqui a seis meses isto fracassou. Por quê?" Cada causa plausível vira um risco RI-n com um jeito de descobrir cedo. |
| Escopo crescendo | **Corte por valor** | Para cada item: o que acontece se não entrar na primeira entrega? Se nada grave, vai para Fora de escopo. |
| Uma só solução na mesa | **Alternativas forçadas** | Gere ao menos duas opções que resolvam o mesmo problema por caminhos diferentes (fazer, comprar, processo, não fazer). |

Regras:

- Pergunte em lote, com `AskUserQuestion` (até 4 perguntas por rodada), sempre com uma opção
  recomendada primeiro quando couber.
- Não invente dado (número, prazo, perfil). O que faltar vira pergunta aberta.
- Fique no problema: tecnologia, tela e tabela não entram no brief; quando o humano trouxer uma,
  registre o porquê dela e trate a solução como opção.
